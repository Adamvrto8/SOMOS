# Accounts and sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional accounts (Google or e-mail code via Supabase) whose progress syncs record by record between devices.

**Architecture:** The device stays the source of truth. Dexie hooks note changed keys in an `outbox`; localStorage
stores (lessons, tests, settings) are diffed against the last state known on the server. One sync round pulls
`rev > cursor`, applies (pending newer local changes win), then pushes. Supabase holds one `records` table with RLS.
`@supabase/supabase-js` is imported dynamically, only for accounts.

**Tech Stack:** Vite + React + TS, Dexie 4, `@supabase/supabase-js@2.117.2`, `fake-indexeddb@6.2.5` (dev, tests), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-accounts-design.md`

Execution: inline (Adam's standing preference, see memory), one commit per task, push at the end.

## Global Constraints

- The account is optional: with no account, or with `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` missing, the app behaves exactly as today and shows no account UI.
- UI texts in `src/i18n/sk.ts` and `src/i18n/en.ts` (same shape); code and comments in English.
- No `any` in data code. Package versions pinned exactly (published ≥ 2 weeks ago).
- Not synced: reminder, DeepL cache (`lookups`), active-lesson memory, TTS voice.
- Sign-out keeps device settings (theme, look, language, sound) and removes the learner data.
- `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e` green before the push.

## Review Focus

1. Signing in on a device with years of attempts: the first upload must go in batches (≤ 500 per request), not one huge request — test in Task 3.
2. Going offline mid-round: a failed push keeps the outbox and the stores' diffs; nothing is marked synced — test in Task 3.
3. A row changed locally while its push was in flight: the outbox entry must survive (its `at` changed) — test in Task 3.
4. Applying a pulled record must not put it back into the outbox (echo loop) — test in Task 1.
5. Sign-out while offline with pending changes asks before wiping — test in Task 5 (e2e) and `pendingChanges()` in Task 3.

### Task 3: Engine

**Files:**
- Create: `src/lib/sync/server.ts`, `src/lib/sync/engine.ts`, `src/lib/sync/engine.test.ts`

**Interfaces:**
- Produces:
  - `interface SyncServer { pull(since: number, limit: number): Promise<RemoteRecord[]>; push(records: SyncRecord[]): Promise<void> }`
  - `class MemoryServer implements SyncServer` (keeps the newer `changedAt`, `rev` counter, `failNext` for tests)
  - `syncOnce(server: SyncServer, now?: number): Promise<{ pulled: number; pushed: number }>`
  - `adoptDevice(): Promise<void>` — every local row into the outbox with `at: 0`
  - `pendingChanges(): Promise<number>` — outbox size + `storeChanges` length
  - `wipeLearnerData(): Promise<void>` — clears the five tables, outbox, lookups, lesson/test stores, sync state
  - `PUSH_BATCH = 500`, `PULL_PAGE = 1000`

Round: pull pages until short → for each record: Dexie kind → skip when a pending outbox entry has `at > changedAt`,
else `runRemote(write/delete)` and drop an entry with `at ≤ changedAt`; store kind → `applyStoreRecord` → save cursor.
Push: outbox entries → records from current rows (missing → `deleted: true`, `changedAt: entry.at || now`), plus
`storeChanges`; in batches; after each batch delete entries whose `at` is unchanged and mark stores pushed.

- [ ] **Step 1: Failing tests:**
  - a local star is pushed; after `wipeLearnerData` and a new round it is back (new device)
  - a remote tombstone deletes the local row; a pending newer local change is kept and pushed instead
  - a pulled record does not re-enter the outbox
  - attempts pulled twice stay one row each
  - `adoptDevice` merges: server-only and device-only rows both end on both sides; same key → server's version
  - 1 200 attempts are pushed in three requests
  - push fails (`failNext`) → outbox and `pendingChanges()` unchanged, cursor saved only for what was applied
  - a row changed again while its push was in flight keeps its outbox entry
- [ ] **Step 2:** run → FAIL. **Step 3:** implement. **Step 4:** pass.
- [ ] **Step 5:** commit `feat(sync): one sync round, adoption and wipe, tested on a memory server`.

### Task 4: Supabase: schema, server, account, scheduler

**Files:**
- Create: `supabase/schema.sql`, `src/lib/sync/supabaseServer.ts`, `src/lib/account.ts`, `src/lib/sync/scheduler.ts`, `src/lib/sync/scheduler.test.ts`
- Modify: `package.json` (`@supabase/supabase-js@2.117.2`), `src/main.tsx` (`startAccount()`), `src/env.d.ts` (env types)

SQL (`supabase/schema.sql`):

```sql
create sequence if not exists public.records_rev;
create table if not exists public.records (
  user_id uuid not null default auth.uid() references auth.users on delete cascade,
  kind text not null,
  key text not null,
  data jsonb,
  deleted boolean not null default false,
  changed_at bigint not null,
  rev bigint not null default nextval('public.records_rev'),
  primary key (user_id, kind, key)
);
create index if not exists records_user_rev on public.records (user_id, rev);
alter table public.records enable row level security;
create policy "own records" on public.records for all using (user_id = auth.uid()) with check (user_id = auth.uid());
grant select, insert, update, delete on public.records to authenticated;
grant usage on sequence public.records_rev to authenticated;

-- The newer change wins; every write takes a new rev so the other devices pull it.
create or replace function public.push_records(items jsonb) returns void language sql security invoker as $$
  insert into public.records (user_id, kind, key, data, deleted, changed_at)
  select auth.uid(), i->>'kind', i->>'key', i->'data', coalesce((i->>'deleted')::boolean, false), (i->>'changedAt')::bigint
  from jsonb_array_elements(items) i
  on conflict (user_id, kind, key) do update
    set data = excluded.data, deleted = excluded.deleted, changed_at = excluded.changed_at, rev = nextval('public.records_rev')
    where public.records.changed_at <= excluded.changed_at;
$$;
grant execute on function public.push_records(jsonb) to authenticated;

create or replace function public.delete_my_account() returns void language sql security definer set search_path = '' as $$
  delete from auth.users where id = auth.uid();
$$;
revoke execute on function public.delete_my_account() from public, anon;
grant execute on function public.delete_my_account() to authenticated;
```

**Interfaces:**
- Produces:
  - `accountsAvailable: boolean` (both env vars set)
  - `interface Account { userId: string; email: string }`, `getAccount()`, `useAccount(): Account | null`
  - `signInWithGoogle()`, `sendCode(email)`, `verifyCode(email, code): Promise<void>`, `completeOAuth(): Promise<boolean>`
  - `signOut({ force }: { force?: boolean }): Promise<'done' | 'pending'>`, `deleteAccount(): Promise<void>`
